How it works
03 / 07
Retrieval-augmented generation

Search first. Ask the model second.

The model does not learn from uploaded files. The app finds relevant text and includes it in each request as temporary context.

01 · INGEST

PDF / TXT / MD

Read text; PDF pages retain page numbers.

02 · CHUNK

~1,000 chars

Normalize text and overlap chunks by 150 characters.

03 · INDEX

SQLite FTS5

Porter stemming + Unicode tokenization.

04 · RETRIEVE

Top excerpts

Keyword match; rank results and take the requested limit.

05 · PROMPT

Instructions + notes

Ask for an answer grounded in the retrieved excerpts.

06 · RESPOND

Local model

Return the response and the source list to the UI.

Search details

The app tokenizes the query, searches up to 12 terms with OR matching, ranks results, and defaults to five excerpts.

Grounding details

Each excerpt is labeled for citation. The system prompt tells the model to use the supplied notes and say when they do not support an answer.

Getting started
04 / 07
A simple study loop

From a file to a focused question.

STEP 01

Start the local model

Open Unsloth Studio, load a compatible GGUF instruct model, and make sure its local API is available.

STEP 02

Add course material

Choose PDF, TXT, or Markdown files in the Sources pane. The app stores uploads in its local documents folder.

STEP 03

Index your files

Select Index. The app extracts text, splits it into overlapping chunks, and writes the search index to SQLite.

STEP 04

Ask and inspect

Choose a mode, write a question or answer, and review the source list under the response.

For PDFs, searchable/selectable text is required. Scanned pages need OCR, which is not included.

Technology
06 / 07
Small, local-first stack

Every layer has a clear job.

Interface

HTML · CSS · JavaScript

Single-page browser UI served by the Python app. No frontend framework or remote service is required.

Web server

Python 3.11–3.13

Python standard-library HTTP server handles the page and local JSON/file endpoints.

Document parsing

pypdf

Extracts selectable text from PDFs and retains page numbers for source references.

Search index

SQLite FTS5

Embedded full-text index; Porter stemming and Unicode-aware tokenization support lightweight keyword retrieval.

Inference server

Unsloth Studio

Serves a loaded local GGUF instruct model through an OpenAI-compatible API.

Model requests

/v1/chat/completions

The app discovers a loaded model ID or accepts UNSLOTH_MODEL. Default generation uses temperature 0.3 and up to 500 tokens.

Design boundaries
07 / 07
Local by design · Evidence matters

Know what stays local—and what to verify.

Local Your study loop

  • The web server binds to 127.0.0.1 on this computer.
  • Uploaded files, extracted text, and the SQLite index stay in local folders.
  • Model requests go to the configured local Unsloth endpoint.
  • The API key can come from the Linux desktop keyring or UNSLOTH_API_KEY.

Current limitations

  • Retrieval is keyword-based, not semantic; use distinctive course terms.
  • Scanned PDFs need OCR. This app does not provide OCR.
  • Answers from small models can be incomplete or wrong; check citations against the original notes.
  • Chat history is not retained after a page refresh.
  • The app retrieves context; it does not fine-tune or change model weights.

Best practice: start with a few clean course files, verify the indexed text, and evaluate answers with a fixed set of questions.
