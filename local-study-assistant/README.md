# Local Study Assistant

A CPU-first, local study assistant for the ITRI626 portfolio. It searches your own course notes with SQLite full-text search, passes relevant excerpts to a local model, and returns answers with source citations. It supports question answering, quiz generation, and feedback on a learner answer through both a command-line tool and a local browser interface.

## Why this design

- **No GPU required for chat:** connect to a GGUF model served locally through Unsloth Studio's OpenAI-compatible API.
- **Low memory overhead:** SQLite FTS5 does retrieval; no separate embedding model or vector database is needed.
- **Grounded responses:** the assistant receives retrieved excerpts and is instructed to cite them or admit when evidence is missing.
- **Fine-tuning is optional:** this laptop has no supported discrete GPU, so do not plan local fine-tuning. The assistant is useful without a fine-tuned model. If the course requires a fine-tuning experiment, ask the lecturer whether an explicitly documented no-GPU limitation or an approved hosted option is acceptable.

## Requirements

- Linux, Python 3.11–3.13 (Unsloth Studio's current requirements list this range)
- Unsloth Studio and a small GGUF instruct model that fits the laptop's memory
- For PDF ingestion: `pypdf`

The development laptop reported 7.4 GiB RAM and integrated Intel graphics. CPU inference will be slower than GPU inference. Start with a small quantized model and a modest context length. The code does not download a model or transmit documents to a cloud service.

## Setup

1. Use Python 3.13 in an isolated environment. Since this project is on a removable drive, create the environment in your Linux home directory to avoid filesystem symlink limitations:

	```text
	python3.13 -m venv ~/.venvs/local-study-assistant
	~/.venvs/local-study-assistant/bin/python -m pip install -r requirements.txt
	```

	Replace `python3.13` with the Python 3.13 executable selected in VS Code if that command is not available in your shell.

2. Install and start Unsloth Studio using its official Linux instructions. Download and load a small GGUF instruct model; given this laptop's 7.4 GiB RAM, begin with a 1–2B parameter model in a 4-bit quantization and keep other applications closed during testing.
3. In Unsloth, create an API key from **Settings → API**. Save it in the Linux desktop keyring with ~/.venvs/local-study-assistant/bin/python study_assistant.py save-key; the prompt hides what you type. The app retrieves it when it starts. UNSLOTH_API_KEY can override the saved key for one terminal session. Never commit or share the key. Unsloth's endpoint is typically on port 8000 or 8888. The app defaults to http://localhost:8888/v1; set UNSLOTH_BASE_URL to the base URL printed by Unsloth if yours differs. The loaded model ID is discovered automatically; optionally set UNSLOTH_MODEL to override it.
4. Add a small set of your course TXT, Markdown, or PDF files in `documents/`, or upload them through the browser interface.
5. Index the files, then ask a question or generate a quiz.

Example commands:

```text
python study_assistant.py ingest
python study_assistant.py ask "What is gradient descent?"
python study_assistant.py quiz "activation functions"
python study_assistant.py grade "My answer is that gradient descent adjusts weights to reduce error."
python study_assistant.py grade "It changes weights to reduce error." --topic "gradient descent"
```

Use the isolated interpreter for commands, for example ~/.venvs/local-study-assistant/bin/python study_assistant.py ask. The key is read from the Linux desktop keyring when the app starts; UNSLOTH_API_KEY overrides it for the current shell. Set UNSLOTH_BASE_URL if Studio uses a different local API URL and UNSLOTH_MODEL to override model discovery. The database and document directory can be changed with STUDY_ASSISTANT_DB and STUDY_ASSISTANT_DOCS.

## Portfolio development plan

1. Record the model name, quantization, RAM use, response time, and observed answer quality.
2. Create a small fixed evaluation set of questions from your notes; check factual accuracy and whether citations support each answer.
3. Add more materials only after verifying PDF extraction and retrieval quality.
4. Keep a learning log of model attempts and lessons learned.
5. Record an introduction/demo video and document setup and usage for the portable environment.

## Current limitations

- The local browser interface does not keep conversation history after the page is refreshed.
- Retrieval is keyword-based, not semantic. Prefer distinctive course terms in prompts.
- PDF support extracts selectable text only; scanned image PDFs need OCR, which is not included.
- This is not a replacement for checking answers against course material. Small CPU models can make mistakes.
- Quiz questions are generated by the model; ask it for answers/feedback separately with `grade`.

## Local browser interface

Start Unsloth Studio and load your model. Save the key in the desktop keyring once using the command in Setup step 3; the prompt hides what you type. The app retrieves it automatically afterward. Then run:

~~~bash
unset UNSLOTH_API_KEY
~/.venvs/local-study-assistant/bin/python study_assistant_web.py
~~~

The interface listens only on this computer and retrieves the API key from the Linux desktop keyring when it starts.
